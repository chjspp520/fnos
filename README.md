# 飞牛 fnOS for Home Assistant

把飞牛 fnOS NAS 接入 Home Assistant 的自定义集成：系统状态、硬盘健康、Docker 容器、虚拟机（**含远程控制**）、文件/相册/影视应用、服务开关、电源操作，全部实体化；并额外提供**同源反向代理 + 前端悬浮窗**，让 NAS 的 Web 界面和虚拟机控制台能直接在 HA 里打开。

- 仓库：<https://github.com/chjspp520/fnos>
- 开发者：**chjspp520** 与 **撸大师** 共同开发（主要是**撸大师**完成集成的开发）
- 维护者：[@chjspp520](https://github.com/chjspp520)
- 版本：**1.0.0**
- 依赖：`websocket-client>=1.6.0`、`pycryptodome>=3.19.0`（HA 会自动安装）

> 数据来自 fnOS 的 WebSocket 私有接口（登录后用 RSA + 会话令牌通信），非官方开放 API。fnOS 升级后若出现字段变动，可能需要在集成里适配。

## 一、功能

### 1. 系统监控（主机设备）

| 类别 | 实体 |
| --- | --- |
| 性能 | CPU 使用率、内存使用率、内存已用/总量、GPU 使用率、风扇转速（含 CPU 温度、风扇模式属性） |
| 网络 | 网络下载速率、网络上传速率、网卡数量（含网卡明细属性） |
| 磁盘 | 磁盘读取速率、磁盘写入速率、硬盘数量、异常硬盘数量、HDD/SSD/USB 数量、硬盘健康状态、存储池 |
| 存储 | 存储总容量、存储已用容量、存储可用容量 |
| 系统 | 系统版本、系统更新、运行时长、本次运行开始时间、未读通知、登录设备、证书数量 |
| 应用 | 应用状态、Docker 容器（汇总）、虚拟机（汇总）、运行中容器、运行中虚拟机、下载中心活动任务/上行/下行、外部访问域名、FN Connect |
| 硬件 | 硬件信息（CPU 型号、核心数、主板、序列号等，JSON 属性） |
| 操作 | 重启、关机（按钮）；远程控制总开关、SSH/SMB/NFS/FTP/WebDAV/DLNA/防火墙（开关）；有可用系统更新、硬盘健康异常（二进制传感器） |

### 2. Docker 容器（每个容器一个设备）

- 传感器：运行状态（含镜像、ID、端口、项目、命令、网络模式、创建时间属性）、CPU 使用率、内存用量、网络收发
- 开关：容器电源（启动 / 停止）
- 按钮：重启容器
- 设备「访问」：容器映射端口聚合的访问链接页

容器新增/删除会自动跟随（60 秒一次增量补齐，不会漏也不能重复建）。

### 3. 虚拟机（每台虚拟机一个设备）

- 传感器：电源状态（含 CPU/内存/OS/IP 属性）、IP 地址、vCPU 数量、内存容量、芯片组、固件、显卡、磁盘容量、MAC 地址、操作系统、控制台地址
- 开关：电源（开机 / 软关机，带乐观状态，按下立即反馈）
- 按钮：重启、强制关机
- **支持远程控制**：直接在 HA 里打开虚拟机的实时画面（键盘鼠标可用），详见下节

### 4. 虚拟机远程控制

不用装客户端、不用开 fnOS 桌面，在 HA 里就能远程操作虚拟机（等同 fnOS 虚拟机 App 的「控制台」）：

- **打开方式**：虚拟机设备的「访问」按钮 → 虚拟机详情页（信息/硬件/磁盘/网络/快照/CPU 曲线）→ 点「打开控制台」；也可以直接使用该设备的「控制台地址」传感器属性里的 `url`
- **实时画面**：控制台是真实的 noVNC 会话，走 HA 同源反代（HTTP + WebSocket 双向透传），键盘、鼠标、剪贴板可用，画面随虚拟机实时刷新
- **前端悬浮窗内打开**：可拖动、可缩放到全屏，多台虚拟机可各开一个窗口互不替换
- **总开关 `switch.fnos_remote_control`（远程控制）**：默认开启、状态持久化（HA 重启后保持上次选择），所有虚拟机共用；关闭后
  - 新建控制台页面 / VNC 数据连接一律拒绝（403）
  - **立即切断**已建立的所有控制台会话，不等浏览器超时
  - 「控制台地址」传感器不再外泄链接，详情页「打开控制台」置灰
  - 开关属性里可看到「活动控制台连接」数
- **友好提示**：虚拟机关机时打开控制台会给出提示页并可一键开机（避免黑屏或连接失败）
- **链接有效期**：签名链接 24 小时有效，集成每 12 小时自动重签，重启 HA 后也会自动重签，无需手动处理

### 5. 文件 / 相册 / 影视应用

- 文件：最近文件数、收藏文件数、回收站文件数、分享链接数
- 相册：最近添加（JSON 属性带 60 张原图地址）、相册服务可用性
- 影视：影视服务可用性
- 每个设备都有「访问」链接与独立悬浮窗页面（文件管理器可浏览/下载/上传；相册照片墙可看大图）

### 6. 远程访问地址（跟随浏览器地址栏）

- 每个设备的「访问」按钮指向 HA 侧签名页面 `/fnos/web?entry=..&target=..`，与「远程地址」传感器读同一个字段，两处永远一致
- 基地址优先级：集成选项里显式填写的地址 → 浏览器心跳上报的 origin（**自动跟随**端口转发/反代的访问地址）→ HA 外部地址 → 内部地址
- fnOS 整站经 HA 同源反代（HTTP + WebSocket），前端模块拦截「访问」点击并在页面内弹出**可拖动、可缩放的悬浮窗**，不同 target 可同时打开

### 7. 聚合实体 `sensor.fnos_all_entities`

一个实体装下整台 NAS 的目录，供前端卡片一屏渲染：

- **state**：fnOS 实体总数（不含自身与禁用实体）
- **属性 `groups[]`**：一台设备一个节点，`{key, name, kind, label, count, entities[]}`，其中 `entities[]` 每项为 `{entity_id, name, state, icon}`
- 容器/虚拟机/应用增减后自动出现在列表里（注册表变化 1 秒防抖、状态变化 5 秒合并、30 秒轮询兜底）
- 大属性默认**不写入 recorder**（绕开单实体属性 16384 字节上限）。若连状态也不要入库：

```yaml
recorder:
  exclude:
    entities:
      - sensor.fnos_all_entities
```

### 8. 固定英文实体 ID

显示名是中文，但 `entity_id` 统一为短英文，方便写模板/前端：

```
sensor.fnos_cpu                     # 主机 CPU
sensor.fnos_storage_total           # 存储总容量
switch.fnos_ssh                     # SSH 服务
switch.fnos_remote_control          # 远程控制总开关
button.fnos_reboot                  # 重启
sensor.fnos_docker_nginx_state      # Docker 容器 nginx 状态
sensor.fnos_vm_windows_10_state     # 虚拟机（标题）状态
sensor.fnos_all_entities            # 聚合实体
```

配置多个 fnOS 条目时会插入条目段（如 `sensor.fnos_192_168_1_10_cpu`）避免抢号；旧版本生成的拼音 ID 会自动迁移到新 ID（唯一 ID / 历史 / 统计保留）。

## 二、安装

### HACS（推荐）

1. HACS → 集成 → 右上角 ⋮ → **自定义存储库**
2. 地址填 `https://github.com/chjspp520/fnos`，类别选「集成」
3. 搜索「飞牛 fnOS」安装，重启 Home Assistant

### 手动

把 `fnos` 整个目录放到 `config/custom_components/fnos`，重启 Home Assistant。

---

## 三、配置

1. 设置 → 设备与服务 → **添加集成** → 搜索「飞牛 fnOS」
2. 填写：

| 字段 | 说明 |
| --- | --- |
| 主机地址 | fnOS 的 IP 或域名 |
| 端口 | 默认 `5666`；HTTPS 版为 `5667` |
| 使用 HTTPS/WSS | 上游启用 HTTPS 时勾选 |
| 用户名 / 密码 | fnOS 账号（建议使用有管理员权限的账号） |

3. 集成 → 配置 → 选项：

| 选项 | 说明 |
| --- | --- |
| 数据刷新间隔 | 10–3600 秒，默认 30 |
| 访问基地址 | 留空则自动跟随浏览器地址栏；也可显式指定（如 `http://nas.example.com:8123`） |

> 提示：设备链接要生效，先在 HA 里打开一次设备页点「访问」，浏览器心跳上报后地址即自动学习并落盘，重启不丢。

本集成自带聚合实体 `sensor.fnos_all_entities`，所以**在房间精灵里只需要配置一个实体**——`entity: sensor.fnos_all_entities`；甚至什么都不配，卡片会自动发现该实体。CPU、内存、硬盘、存储池、Docker 容器、虚拟机、服务开关、电源按钮等角色，全部从聚合实体的 `groups[]` 属性里自动定位，卡片不写死任何实体 ID。

```yaml
# 示意：房间精灵里某个按钮点开「飞牛 NAS」卡片
tap_action:
  action: popup_card
  card:
    type: fnos                      # 飞牛全实体卡片
    entity: sensor.fnos_all_entities # 唯一需要配置的实体
```



可选参数（都有默认值，可全部省略）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `entity` | `sensor.fnos_all_entities` | 聚合实体；配了就用配的 |
| `name` | `飞牛 fnOS` | 卡片标题 |
| `icon` | 聚合实体图标 | 标题图标 |
| `accent` | 琥珀橙 `#f59e0b` | 主色 |
| `popup_width` | `900px` | 弹窗宽度（兼容 `width`） |
| `popup_position` | `center` | 弹窗位置 |
| `confirm_power` | `true` | 重启/关机是否二次确认 |

三种打开方式：

1. `tap_action.action: popup_card` + `card.type: fnos`（弹窗内卡片）
2. `tap_action.action: card` + `type: fnos`（直接弹卡片）
3. `standalone_type: fnos`（独立模式，整卡就是一页飞牛面板）

好处：NAS 上新增一个 Docker 容器或虚拟机时，聚合一刷新，房间精灵的卡片就自动多出对应条目，**不需要再改任何前端配置**。

## 五、安全说明

- 「远程控制」开关（`switch.fnos_remote_control`）关闭后：拒绝新建 noVNC 控制台连接、立即切断所有已建立的控制台会话，并且「控制台地址」传感器不再外泄链接。开关状态持久化，HA 重启后保持。
- 悬浮窗页面全部经 HA 同源反代，鉴权模型为「HA 标准 authSig（入口页）+ 24 小时随机代理票据（页内请求）」，票据只授予对应那台 fnOS，风险面与常见签名链接一致。
- 浏览器地址心跳必须携带 HA 登录态，拿不到就不上报，避免被记为失败登录。

## 六、常见问题

**Q：添加集成提示「无法连接」？**
检查端口（HTTPS 版是 5667，且要勾「使用 HTTPS/WSS」）、账号密码、fnOS 防火墙。

**Q：设备「访问」打开的页面打不开 / 白屏？**
先在 HA 里打开一次设备页点「访问」以学习浏览器地址；若 HA 在反代后面，可在选项里显式填写「访问基地址」。

**Q：实体 ID 和我看到的旧教程不一样（拼音 vs 英文）？**
本集成统一用短英文 ID，旧版本生成的拼音 ID 会在加载后自动迁移，无需手动改。

**Q：虚拟机控制台打不开 / 黑屏？**
先确认虚拟机处于运行状态（关机时会显示提示页，可一键开机）；再确认 `switch.fnos_remote_control` 是开启的（关闭时控制台入口置灰、VNC 连接被拒）。首次打开需要在浏览器里加载 noVNC 前端资源，稍等几秒。

**Q：`sensor.fnos_all_entities` 让数据库变大？**
它的大属性默认不写 recorder；状态本身也建议按上面的 `recorder.exclude` 排除。

**Q：扫描/运行数据多久更新？**
跟随「数据刷新间隔」（默认 30 秒）。按钮/开关操作后会主动补刷；虚拟机电源状态带乐观更新，避免先弹回再跳过去。
